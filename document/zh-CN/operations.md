# 运维、升级与排障

[English](../en/operations.md) · [手册首页](README.md)

## 日常管理

固定程序目录、IJOB_HOME、运行账号和访问地址。程序包与运行数据分开保存；所有节点须有独立本地目录。启停、状态、日志命令见安装说明。停止平台前确认业务窗口，先停用需要暂停的调度并观察在途运行；停止平台不等于撤销外部业务副作用。

工作台可查看节点在线、新鲜度及扫描/续租状态；运行中心查看实际实例、执行节点、日志和拓扑。UNKNOWN、过期或不可用不等于零负载。不要仅根据网页能打开判定 Worker 和调度健康。

## 备份和恢复

SQLite 入门安装采用停机一致备份：停用练习调度、优雅停止并确认进程退出，备份整个 IJOB_HOME（包括配置、installation.properties、setup.complete、runtime、数据库及原 AES 密钥）。不要只复制运行中的 platform.db；WAL 状态可能尚未合并。备份应限制权限并按组织要求加密，不能提交到 Git。

恢复演练使用新目录和独立端口；保留原备份不动，恢复后重新核对绝对路径、权限、配置和数据。复制的 PID/进程控制记录不代表当前有运行进程，启动器必须验证身份；不得按其中 PID 直接结束进程。程序版本与数据库能力必须兼容。验证登录、已保存任务/版本、历史运行和加密资源可读性，再运行独立样例任务。

服务数据库使用相应数据库的备份/恢复机制，并与应用配置和原密钥共同管理。恢复目标是新库，不指向现有业务库。RPO/RTO 必须通过本环境实测，历史演练时间不代表生产承诺。

恢复到新目录时，原生 SQLite 的 spring.datasource.url 应指向新 runtime/platform.db。Docker 保留容器内数据库地址和 8080 端口，但须修改复制的 compose.yaml：使用新项目名，将两个绑定 source 分别改为新目录的 application.properties 和 runtime；配置与 runtime 保持 UID/GID 10001 的受限权限。修改后通过对应程序包的 start-docker.sh --recreate 启动。

## 升级与回退

1. 记录当前包哈希、源码标识、配置位置和数据库版本，完成可恢复备份。
2. 将新包解压到新程序目录，核验 SHA256SUMS 和候选测试结果；不要覆盖运行中的文件。
3. 停止旧实例，用原 IJOB_HOME 启动新包。保留数据库、配置和原密钥，已有安装不会被初始化覆盖。
4. 核验就绪、登录、资源、版本、历史和一个独立样例；记录部署时刻与结果。
5. 若需回退，先确认新版本是否改变数据库结构或产生业务写入，再选择兼容旧包或在新目标恢复匹配备份。不能假定更换 JAR 就能撤销迁移或外部操作。

当前产品保持 1.0.0，正式新安装使用 V1。历史旧库不得直接接到正式应用；历史转换工具与资源需要独立构建和迁移审核，不属于快速安装流程。当前版本跨数据库产品迁移没有一键承诺。

## 多账号、集群与生产入口

默认 STATIC 为配置账号。需要 DATABASE 多账号时，在单机维护窗口备份后按受控引导流程切换：仅在账号表为空时临时开启 bootstrap，用既有管理员配置建立首个账号，完成强制改密，然后关闭 bootstrap 并重启验证。账号表非空时应使用已有启用管理员；引导开关不会重置账号或绕过无管理员保护。

SQLite 仅单实例。CLUSTER 使用共享服务数据库、一致认证和 AES/Token 配置、独立节点名及数据目录，先 A 就绪再 B。不得让 STANDALONE 与 CLUSTER 同库混跑，也不要单独修改某节点密钥来试错。现有集群认证/密钥变化须制定兼容迁移方案。任务执行具有至少一次语义，外部写入应使用业务幂等键；同宿主双进程不等于物理高可用。

生产入口需要按目标环境配置 TLS、访问控制、readiness 摘流、上传/SSE 超时、告警接收和容量。默认镜像只提供基础运行组件；脚本解释器、Local JAR 和业务文件需要明确提供并验收。不要挂载 docker.sock 或使用 privileged 来补齐任务能力。

## 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 无法启动或超时 | Java 版本 → IJOB_HOME/权限 → 端口 → 应用日志 → 数据库连接；超时不代表进程已退出 |
| 修改配置无效 | 是否编辑正确 home → 是否重复键 → 启动参数/环境覆盖 → 是否重启/重建容器 |
| 登录失败 | 当前认证模式和账号来源 → 实际访问节点 → 日志/审计；不要删除账号表或密钥 |
| 任务不运行 | 任务/作业启用 → 当前发布版本 → 分组和 Worker → 并发限制 → 实例状态 |
| 调度不触发 | 目标启用 → 调度启用 → 全局开关 → 时区/有效期/日历 → SCHEDULER 节点 |
| 文件或解释器不存在 | 检查执行 Worker/容器内部的路径和权限，而非浏览器电脑 |
| 主库恢复后节点仍受保护 | 核验数据库健康，按 A 就绪再 B 的顺序受控重启；不清空协调记录 |

提交问题时提供版本、源码/制品哈希、操作步骤、实例 ID、脱敏错误和预期行为，不附完整 application.properties、数据库、令牌或连接口令。
