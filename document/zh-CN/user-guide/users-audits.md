# 用户、权限与审计

[English](../../en/user-guide/users-audits.md) · [手册首页](../README.md)

业务账号角色决定页面和 API 动作权限，节点角色决定服务器职责。两者独立。本页适用于 1.0.0 的角色策略；先确认[账号模式](../operations/accounts.md)。

## 角色与动作矩阵

“可”仍需满足对象状态、路由等业务条件；“条件允许”见下方说明。

| 动作 | ADMIN | OPERATOR | VIEWER |
| --- | --- | --- | --- |
| 查看概要、定义列表 | 可 | 可 | 可 |
| 创建、修改任务或作业 | 可 | 不可 | 不可 |
| 发布定义版本 | 可 | 不可 | 不可 |
| 手动执行 | 可 | 可 | 不可 |
| 停止、暂停、恢复、重试 | 可 | 可 | 不可 |
| 审批 | 条件允许 | 条件允许 | 不可 |
| 创建/修改资源、测试连接 | 可 | 不可 | 不可 |
| 查看受敏感权限保护的定义详情 | 可 | 不可 | 不可 |
| 查看日志及输入输出详情 | 可 | 不可 | 不可 |
| 发布入站事件 | 可 | 不可 | 不可 |
| 配置包导入、导出 | 可 | 不可 | 不可 |
| 维护用户 | DATABASE 模式可用 | 不可 | 不可 |
| 查看操作审计 | 可 | 不可 | 不可 |
| 修改自己的密码 | 按账号模式 | 按账号模式 | 按账号模式 |

## 动作不可用时如何判断

| 场景 | 条件 | 建议操作 |
| --- | --- | --- |
| 新建、编辑、发布不可用 | 需要 CONFIGURATION_WRITE，仅 ADMIN 拥有 | 使用管理员完成配置；运行交给 OPERATOR |
| 手动执行或实例控制不可用 | 需要 EXECUTION_CONTROL；实例状态还需允许相应动作 | 使用 ADMIN/OPERATOR，并查看实例当前状态 |
| 审批不可用 | 需要 APPROVAL_DECIDE、允许操作人名单及可处理的等待状态 | 确认当前账号被配置为允许操作人；已处理/过期记录不可当作新审批 |
| 详情不可见 | SENSITIVE_READ 与概要读取不同 | 需要详情时使用 ADMIN；列表可见不等于字段可见 |
| 用户管理不可用 | STATIC 账号来自配置；DATABASE 才提供日常数据库用户维护 | 先确认模式，不通过切换模式代替密码恢复 |
| 登录后多数操作被拒绝 | 账号要求首次改密 | 先完成自己的密码更新 |

## 秘密字段与资源配置

SENSITIVE_READ 不代表任意秘密明文回显。资源详情按字段脱敏或显示已配置状态；编辑时使用保留、替换或清除语义。未显示旧口令不等于旧口令为空。资源、脚本和业务日志可能包含敏感业务内容，按角色授予访问。

## 用户管理与审计

1. DATABASE 模式下使用 ADMIN 进入系统管理 → 用户，创建所需角色的账号。
2. 保留至少一个启用的管理员；首次登录按提示修改密码。
3. 用独立会话检查该账号可以查看和执行的动作。
4. 使用 ADMIN 打开操作审计，按操作人、动作、对象、时间和结果定位记录。

STATIC 模式通过受控私有配置维护账号。NONE/DEVELOPMENT 不能作为正式部署认证方案。审计记录证明平台操作发生过，不证明外部事务已回滚或业务结果已完成。
