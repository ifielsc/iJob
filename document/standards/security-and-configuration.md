# 安全与配置规范

源码仅保留可公开审查的模板、变量名与说明。真实数据库密码、SFTP 私钥、AES 密钥、Agent token、通知渠道凭据及运行账号存放在对应环境 `secrets/`，按最小权限限制读取；资源清单只写文件引用和用途，不写秘密值。环境之间不得隐式共用秘密或旧服务。

默认 STATIC 认证且 bootstrap 关闭。初始化由 setup 工具在源码树外生成配置；不能给新环境预置通用账户密码。切换认证或持久化模式按首次启动文档执行，权限检查、审计、响应脱敏与 secret 保留/替换/清除契约同时维护。

SSH/SFTP 首次连接登记并核对主机指纹；明确受信主机、端口、账号权限与远程根目录。测试 fixture 创建独立身份，业务使用不能沿用测试信任或自动接受未知主机。配置变更记录生效时间、来源、验证与回退方法。

发布制品绑定源码提交、构建工具链、哈希和验证证据。源码同步不等于旧发布包自动更新；重新发布另建候选。不得把未运行的容器、真实消息源、五库或多节点验收算作已通过。依赖清点与许可审核遵循既有 P3 边界。

漏洞报告按实际交付范围区分：Native/JAR 安装由用户准备和维护宿主操作系统，宿主系统包不因用于测试就成为产品随包依赖；仅存在于测试 VM 或构建工具环境的风险单列为环境风险。分发 Docker 镜像时，最终镜像内实际携带的系统库、工具和 JRE 属于交付组件，须扫描并记录版本、适用性及处置，不能归为用户自备系统。容器共享运行环境的内核，但镜像内的发行版用户空间与宿主发行版可以不同；更换宿主 Linux 不会自动更新镜像内的系统包。镜像中的 Ubuntu 命中应标为“Docker 运行镜像内的 Ubuntu 用户空间包”，不外推为 Native 安装包命中，不表示产品只支持 Ubuntu，也不代表所有 Linux 组合已经验证。
